# 5장. 스칼라 함수

## 학습 목표

- 스칼라 함수와 집계 함수의 차이를 설명할 수 있다
- 문자열·숫자·날짜 함수를 사용해 데이터를 원하는 형태로 가공할 수 있다
- 데이터 타입을 변환하고 원하는 서식으로 출력할 수 있으며, 세 가지 형변환 표기의 차이를 설명할 수 있다
- `COALESCE`, `NULLIF`로 NULL을 안전하게 처리할 수 있다
- `CASE` 식으로 조건에 따라 다른 값을 표시할 수 있다

---

## 5.1 함수란 무엇인가

4장에서 우리는 테이블에 저장된 값을 **있는 그대로** 조회했습니다. 하지만 실무에서는 저장된 값을 그대로 쓰기보다 가공해서 보여줘야 할 때가 많습니다. 가격에 천 단위 쉼표를 넣거나, 이메일에서 도메인만 떼어내거나, 전화번호가 없는 고객에게 "미등록"이라고 표시하는 식으로요.

이때 사용하는 것이 **함수**(**Function**)입니다. 함수는 값을 입력받아 정해진 규칙으로 처리한 뒤 결과를 돌려주는 도구입니다.

```
입력값  →  [ 함수 ]  →  결과값
```

SQL의 함수는 크게 두 종류로 나뉩니다.

| 구분 | 설명 | 예 |
|---|---|---|
| **스칼라 함수** | **행 하나마다** 하나의 결과를 돌려줌 | `UPPER('abc')` → `ABC` |
| **집계 함수** | **여러 행을 묶어** 하나의 결과를 돌려줌 | `SUM(price)` → 전체 합계 |

이 장에서 다루는 것은 **스칼라 함수**입니다. 10개의 행을 조회하면 결과도 10개의 행으로 나오며, 행의 개수가 바뀌지 않습니다. 여러 행을 하나로 요약하는 집계 함수는 6장에서 다룹니다.

> PostgreSQL에는 수백 개의 함수가 있습니다. 이 장에서는 실무에서 자주 쓰는 것만 다루며, 더 많은 함수 목록은 **부록 B**를 참고하세요. 함수를 외우려 하기보다 "이런 일을 하는 함수가 있다"는 감각을 익히는 것이 중요합니다.

## 5.2 문자열 함수

### 길이와 대소문자

| 함수 | 설명 |
|---|---|
| `LENGTH(문자열)` | 글자 수를 반환 |
| `UPPER(문자열)` | 모두 대문자로 변환 |
| `LOWER(문자열)` | 모두 소문자로 변환 |

**예제 5-1.** 상품명의 글자 수를 함께 조회합니다.

```sql
SELECT product_name, LENGTH(product_name) AS 글자수
FROM products;
```

| product_name | 글자수 |
|---|---|
| 무선 이어폰 | 6 |
| 블루투스 키보드 | 8 |
| 스탠드 조명 | 6 |
| 머그컵 | 3 |
| ... 외 6건 | |

PostgreSQL의 `LENGTH`는 **바이트가 아닌 글자 수**를 세므로 한글도 한 글자로 계산됩니다. 공백도 한 글자로 포함된다는 점에 주의하세요.

**예제 5-2.** 이메일을 대문자로 변환해 조회합니다.

```sql
SELECT customer_name, email, UPPER(email) AS 대문자
FROM customers;
```

| customer_name | email | 대문자 |
|---|---|---|
| 김민준 | minjun@example.com | MINJUN@EXAMPLE.COM |
| 이서연 | seoyeon@example.com | SEOYEON@EXAMPLE.COM |
| 박도윤 | doyoon@example.com | DOYOON@EXAMPLE.COM |
| ... 외 2건 | | |

원본 데이터는 바뀌지 않습니다. 함수는 조회 결과만 가공할 뿐, 테이블에 저장된 값은 그대로입니다.

### 문자열 연결 — `||` 와 CONCAT

두 문자열을 이어 붙일 때는 파이프 두 개(`||`) 연산자나 `CONCAT` 함수를 사용합니다.

**예제 5-3.** 고객 이름 뒤에 "님"을 붙입니다.

```sql
SELECT customer_name, customer_name || '님' AS 인사말
FROM customers;
```

| customer_name | 인사말 |
|---|---|
| 김민준 | 김민준님 |
| 이서연 | 이서연님 |
| 박도윤 | 박도윤님 |
| ... 외 2건 | |

여기서 NULL과 관련된 중요한 차이가 나타납니다. `||`는 연결 대상 중 하나라도 NULL이면 **전체 결과가 NULL**이 되지만, `CONCAT` 함수는 NULL을 빈 문자열처럼 취급하고 무시합니다.

**예제 5-4.** 전화번호가 NULL인 고객에서 두 방식의 차이를 확인합니다.

```sql
SELECT customer_name, phone,
       customer_name || phone AS 연결,
       CONCAT(customer_name, phone) AS concat결과
FROM customers
WHERE customer_id IN (1, 3);
```

| customer_name | phone | 연결 | concat결과 |
|---|---|---|---|
| 김민준 | 010-1111-2222 | 김민준010-1111-2222 | 김민준010-1111-2222 |
| 박도윤 | *(NULL)* | *(NULL)* | 박도윤 |

> **자주 하는 실수**: `||`로 여러 컬럼을 이어 붙였는데 결과가 통째로 비어 나온다면, 중간에 NULL인 컬럼이 섞여 있을 가능성이 큽니다. 5.7절의 `COALESCE`와 함께 쓰면 해결됩니다.

### 잘라내기와 바꾸기

| 함수 | 설명 |
|---|---|
| `SUBSTRING(문자열 FROM 시작 FOR 길이)` | 지정한 위치부터 잘라냄 (시작 위치는 1부터) |
| `SPLIT_PART(문자열, 구분자, 번째)` | 구분자로 나눈 뒤 N번째 조각을 반환 |
| `REPLACE(문자열, 찾을값, 바꿀값)` | 특정 문자열을 다른 문자열로 치환 |
| `TRIM(문자열)` | 앞뒤 공백을 제거 |
| `LPAD(문자열, 길이, 채울문자)` | 왼쪽을 채워 지정한 길이로 맞춤 |

**예제 5-5.** 이메일에서 아이디와 도메인을 분리합니다.

```sql
SELECT email,
       SPLIT_PART(email, '@', 1) AS 아이디,
       SPLIT_PART(email, '@', 2) AS 도메인
FROM customers;
```

| email | 아이디 | 도메인 |
|---|---|---|
| minjun@example.com | minjun | example.com |
| seoyeon@example.com | seoyeon | example.com |
| doyoon@example.com | doyoon | example.com |
| ... 외 2건 | | |

**예제 5-6.** 상품명에서 공백을 제거합니다.

```sql
SELECT product_name, REPLACE(product_name, ' ', '') AS 공백제거
FROM products;
```

| product_name | 공백제거 |
|---|---|
| 무선 이어폰 | 무선이어폰 |
| 블루투스 키보드 | 블루투스키보드 |
| 스탠드 조명 | 스탠드조명 |
| 머그컵 | 머그컵 |
| ... 외 6건 | |

**예제 5-7.** 상품 번호를 5자리 코드 형식으로 만듭니다.

```sql
SELECT product_id, LPAD(product_id::TEXT, 5, '0') AS 상품코드
FROM products;
```

| product_id | 상품코드 |
|---|---|
| 1 | 00001 |
| 2 | 00002 |
| 3 | 00003 |
| ... 외 7건 | |

`product_id::TEXT`는 숫자를 문자열로 바꾸는 형변환입니다. 5.5절에서 자세히 다룹니다.

## 5.3 숫자 함수

| 함수 | 설명 | 예 | 결과 |
|---|---|---|---|
| `ROUND(숫자[, 자릿수])` | 반올림 | `ROUND(12345.678, 1)` | `12345.7` |
| `TRUNC(숫자[, 자릿수])` | 버림 (자르기) | `TRUNC(12345.678, 1)` | `12345.6` |
| `CEIL(숫자)` | 올림 | `CEIL(12345.1)` | `12346` |
| `FLOOR(숫자)` | 내림 | `FLOOR(12345.9)` | `12345` |
| `ABS(숫자)` | 절댓값 | `ABS(-500)` | `500` |
| `MOD(a, b)` | 나머지 | `MOD(10, 3)` | `1` |
| `POWER(a, b)` | 거듭제곱 | `POWER(2, 10)` | `1024` |

**예제 5-8.** 모든 상품의 10% 할인가를 계산합니다.

```sql
SELECT product_name, price, ROUND(price * 0.9) AS 할인가
FROM products;
```

| product_name | price | 할인가 |
|---|---|---|
| 무선 이어폰 | 89000.00 | 80100 |
| 블루투스 키보드 | 45000.00 | 40500 |
| 스탠드 조명 | 32000.00 | 28800 |
| 머그컵 | 12000.00 | 10800 |
| ... 외 6건 | | |

`ROUND`의 두 번째 인자는 **남길 소수점 자릿수**입니다. 생략하면 정수로 반올림합니다. 음수를 주면 정수 부분에서 반올림되어, `ROUND(12345.678, -3)`은 `12000`이 됩니다.

**예제 5-9.** 가격을 3등분한 금액을 소수점 둘째 자리까지 표시합니다.

```sql
SELECT product_name, price, ROUND(price / 3, 2) AS 삼등분
FROM products;
```

| product_name | price | 삼등분 |
|---|---|---|
| 무선 이어폰 | 89000.00 | 29666.67 |
| 블루투스 키보드 | 45000.00 | 15000.00 |
| 스탠드 조명 | 32000.00 | 10666.67 |
| ... 외 7건 | | |

## 5.4 날짜/시간 함수

### 현재 날짜와 시각

| 함수 | 반환 값 |
|---|---|
| `CURRENT_DATE` | 오늘 날짜 |
| `CURRENT_TIME` | 현재 시각 |
| `CURRENT_TIMESTAMP` | 현재 날짜와 시각 |

```sql
SELECT CURRENT_DATE AS 오늘, CURRENT_TIMESTAMP AS 지금;
```

이 결과는 실행하는 시점에 따라 달라지므로, 아래 예제들은 결과를 확인하기 쉽도록 테이블에 저장된 고정된 날짜를 사용합니다.

### 날짜 계산

날짜에 정수를 더하거나 빼면 **일**(day) **단위**로 계산됩니다. 더 세밀하게 지정하려면 `INTERVAL`을 사용합니다.

**예제 5-10.** 주문일로부터 3일 뒤를 배송 예정일로 계산합니다.

```sql
SELECT order_id, order_date, order_date + 3 AS 배송예정일
FROM orders;
```

| order_id | order_date | 배송예정일 |
|---|---|---|
| 1 | 2025-06-01 | 2025-06-04 |
| 2 | 2025-06-03 | 2025-06-06 |
| 3 | 2025-06-10 | 2025-06-13 |
| 4 | 2025-06-12 | 2025-06-15 |
| 5 | 2025-06-15 | 2025-06-18 |
| 6 | 2025-07-01 | 2025-07-04 |

`INTERVAL`을 쓰면 `'3 days'`, `'2 months'`, `'1 year'`처럼 단위를 직접 지정할 수 있습니다.

```sql
SELECT order_id, order_date + INTERVAL '2 months' AS 두달후
FROM orders;
```

날짜끼리 빼면 **며칠 차이인지** 정수로 나옵니다.

```sql
SELECT DATE '2025-07-01' - DATE '2024-01-15' AS 일수차이;
```

| 일수차이 |
|---|
| 533 |

> 문자열 앞에 붙은 `DATE`는 "이 문자열을 날짜로 해석하라"는 표시입니다. 이것을 붙이지 않으면 오류가 나는데, 그 이유는 5.5절에서 자세히 다룹니다.

년·월·일 단위로 보고 싶다면 `AGE` 함수를 사용합니다.

```sql
SELECT AGE(DATE '2025-07-01', DATE '2024-01-15') AS 기간;
```

| 기간 |
|---|
| 1 year 5 mons 17 days |

### 날짜에서 일부만 추출 — EXTRACT

**예제 5-11.** 고객의 가입 연도와 월을 추출합니다.

```sql
SELECT customer_name, join_date,
       EXTRACT(YEAR FROM join_date) AS 년,
       EXTRACT(MONTH FROM join_date) AS 월
FROM customers;
```

| customer_name | join_date | 년 | 월 |
|---|---|---|---|
| 김민준 | 2024-01-15 | 2024 | 1 |
| 이서연 | 2024-02-20 | 2024 | 2 |
| 박도윤 | 2024-03-05 | 2024 | 3 |
| ... 외 2건 | | | |

`YEAR`, `MONTH`, `DAY` 외에 `HOUR`, `MINUTE`, `DOW`(요일) 등을 추출할 수 있습니다.

### 기준 시점으로 자르기 — DATE_TRUNC

`DATE_TRUNC`는 지정한 단위 아래를 잘라내어 "해당 월의 1일", "해당 연도의 1월 1일" 같은 기준 시점을 만듭니다. 월별 집계를 할 때 유용하며, 6장에서 다시 만나게 됩니다.

**예제 5-12.** 각 주문이 속한 달의 1일을 구합니다.

```sql
SELECT order_id, order_date, DATE_TRUNC('month', order_date)::DATE AS 월초
FROM orders;
```

| order_id | order_date | 월초 |
|---|---|---|
| 1 | 2025-06-01 | 2025-06-01 |
| 2 | 2025-06-03 | 2025-06-01 |
| 3 | 2025-06-10 | 2025-06-01 |
| ... 외 3건 | | |

> `DATE_TRUNC`는 시각 정보까지 포함된 타입을 돌려주므로, 날짜만 필요하다면 위처럼 `::DATE`를 붙여 정리하면 결과가 깔끔합니다.

## 5.5 형변환 — CAST

숫자를 문자열로, 문자열을 날짜로 바꾸는 것처럼 데이터 타입을 바꾸는 것을 **형변환**(**Type Casting**)이라고 합니다. PostgreSQL에서는 두 가지 방법을 쓸 수 있습니다.

```
[문법]
CAST(값 AS 타입)     -- 표준 SQL 방식
값::타입             -- PostgreSQL 고유 방식 (더 간결함)
```

**예제 5-13.** 여러 형변환을 확인합니다.

```sql
SELECT '123'::INTEGER + 1        AS 결과1,
       CAST('2025-06-01' AS DATE) AS 결과2,
       89000::TEXT || '원'       AS 결과3;
```

| 결과1 | 결과2 | 결과3 |
|---|---|---|
| 124 | 2025-06-01 | 89000원 |

`결과1`이 `1231`이 아니라 `124`인 점에 주목하세요. 문자열 `'123'`을 숫자로 바꾼 뒤 더했기 때문에 산술 덧셈이 일어났습니다. 형변환을 하지 않고 `'123' || 1`이라고 썼다면 문자열 연결이 되어 `1231`이 나옵니다.

**예제 5-14.** 소수점이 있는 가격을 정수로 변환합니다.

```sql
SELECT price, price::INTEGER AS 정수변환
FROM products;
```

| price | 정수변환 |
|---|---|
| 89000.00 | 89000 |
| 45000.00 | 45000 |
| 32000.00 | 32000 |
| ... 외 7건 | |

> **자주 하는 실수**: 변환할 수 없는 값을 변환하면 오류가 발생합니다. `'abc'::INTEGER`는 `invalid input syntax for type integer` 오류를 냅니다. 형변환은 "형식이 맞는 값"에만 통한다는 점을 기억하세요.

### 타입 이름을 앞에 붙이는 표기 — `DATE '2025-07-01'`

5.4절에서 아래와 같은 문장을 본 적이 있습니다.

```sql
SELECT DATE '2025-07-01' - DATE '2024-01-15' AS 일수차이;
```

여기서 문자열 앞에 붙은 `DATE`는 무엇일까요? 이것은 **타입 지정 리터럴**(**Typed Literal**)이라고 하며, "이 문자열 상수를 date 타입으로 해석하라"는 뜻입니다. 넓게 보면 형변환의 한 형태이고, 실제로 아래 세 가지는 **완전히 같은 결과**를 냅니다.

```sql
SELECT DATE '2025-07-01' - DATE '2024-01-15'                 AS a,  -- 타입 지정 리터럴
       '2025-07-01'::DATE - '2024-01-15'::DATE               AS b,  -- :: 방식
       CAST('2025-07-01' AS DATE) - CAST('2024-01-15' AS DATE) AS c; -- CAST 방식
```

| a | b | c |
|---|---|---|
| 533 | 533 | 533 |

#### 왜 타입을 지정해야 할까요

작은따옴표로만 감싼 값은 PostgreSQL 입장에서 아직 타입이 정해지지 않은 상태입니다. 이 상태를 `unknown` 타입이라고 부릅니다.

```sql
SELECT pg_typeof(DATE '2025-07-01') AS 타입지정, pg_typeof('2025-07-01') AS 따옴표만;
```

| 타입지정 | 따옴표만 |
|---|---|
| date | unknown |

타입이 정해지지 않은 두 값을 빼려고 하면, PostgreSQL은 어떤 뺄셈을 해야 할지 판단하지 못하고 오류를 냅니다.

```sql
SELECT '2025-07-01' - '2024-01-15';
```

```
ERROR:  operator is not unique: unknown - unknown
HINT:  Could not choose a best candidate operator. You might need to add explicit type casts.
```

그래서 날짜끼리 계산할 때는 **적어도 한쪽에** 타입을 명시해야 합니다. 한쪽만 지정해도 나머지가 그에 맞춰 해석되므로 아래도 정상 동작합니다.

```sql
SELECT DATE '2025-07-01' - '2024-01-15' AS 일수차이;
```

| 일수차이 |
|---|
| 533 |

다만 읽는 사람이 의도를 바로 알 수 있도록 **양쪽 모두 타입을 명시하는 편**을 권장합니다.

#### `::` 와의 결정적인 차이

타입 지정 리터럴은 **문자열 상수 앞에만** 쓸 수 있습니다. 컬럼 이름 앞에는 쓸 수 없다는 점이 `::`나 `CAST`와의 가장 큰 차이입니다.

```sql
-- 오류: 컬럼에는 이 표기를 쓸 수 없습니다
SELECT DATE order_date FROM orders;
```

```
ERROR:  column "date" does not exist
```

PostgreSQL이 `DATE`를 타입 이름이 아니라 `date`라는 이름의 컬럼으로 해석했기 때문입니다. 컬럼의 타입을 바꾸려면 `::`나 `CAST`를 써야 합니다.

```sql
SELECT order_date::TIMESTAMP FROM orders;
```

정리하면 이렇습니다.

| 표기 | 상수에 사용 | 컬럼·수식에 사용 |
|---|---|---|
| `DATE '2025-07-01'` | 가능 | **불가능** |
| `'2025-07-01'::DATE` | 가능 | 가능 |
| `CAST('2025-07-01' AS DATE)` | 가능 | 가능 |

#### 날짜 말고도 쓸 수 있습니다

이 표기는 date 전용이 아니라 다른 타입에도 동일하게 적용됩니다.

```sql
SELECT INTEGER '123' + 1                        AS 정수,
       TIMESTAMP '2025-07-01 14:30:00'          AS 날짜시각,
       INTERVAL '3 days'                        AS 기간;
```

| 정수 | 날짜시각 | 기간 |
|---|---|---|
| 124 | 2025-07-01 14:30:00 | 3 days |

실무에서는 날짜, 시각, 기간을 상수로 쓸 때 이 표기가 특히 자주 보입니다. 특히 `INTERVAL '3 days'`는 앞 절에서 이미 사용했던 표기이며, 사실 같은 원리였다는 것을 이제 알 수 있습니다.

> **정리**: 형변환 방법은 세 가지지만, 컬럼에도 쓸 수 있는 `::`가 가장 범용적입니다. 이 교재에서는 상수 날짜를 쓸 때만 `DATE '...'` 표기를 사용하고, 그 외에는 `::`를 사용합니다.

## 5.6 서식 지정 — TO_CHAR, TO_DATE, TO_NUMBER

`CAST`는 타입만 바꿀 뿐 **모양**을 정하지는 못합니다. 천 단위 쉼표를 넣거나 날짜를 "2025년 06월 01일" 형태로 보여주려면 `TO_CHAR`를 사용합니다.

```
[문법]
TO_CHAR(값, '서식')
```

**예제 5-15.** 가격에 천 단위 쉼표를 넣습니다.

```sql
SELECT product_name, price, TO_CHAR(price, 'FM999,999,999') AS 가격표시
FROM products;
```

| product_name | price | 가격표시 |
|---|---|---|
| 무선 이어폰 | 89000.00 | 89,000 |
| 블루투스 키보드 | 45000.00 | 45,000 |
| 스탠드 조명 | 32000.00 | 32,000 |
| 머그컵 | 12000.00 | 12,000 |
| ... 외 6건 | | |

서식의 `9`는 숫자 한 자리를 의미하고, 맨 앞의 `FM`은 자릿수가 남을 때 생기는 **불필요한 공백을 제거**하라는 표시입니다. `FM`을 빼면 결과 앞에 공백이 붙습니다.

**예제 5-16.** 주문일을 한글 형식으로 표시합니다.

```sql
SELECT order_id, order_date, TO_CHAR(order_date, 'YYYY년 MM월 DD일') AS 한글날짜
FROM orders;
```

| order_id | order_date | 한글날짜 |
|---|---|---|
| 1 | 2025-06-01 | 2025년 06월 01일 |
| 2 | 2025-06-03 | 2025년 06월 03일 |
| 3 | 2025-06-10 | 2025년 06월 10일 |
| ... 외 3건 | | |

자주 쓰는 날짜 서식 기호는 다음과 같습니다.

| 기호 | 의미 | 예 |
|---|---|---|
| `YYYY` | 4자리 연도 | 2025 |
| `MM` | 2자리 월 | 06 |
| `DD` | 2자리 일 | 01 |
| `HH24` | 24시간제 시 | 14 |
| `MI` | 분 | 30 |
| `SS` | 초 | 05 |

반대 방향의 변환도 있습니다. `TO_DATE`는 문자열을 날짜로, `TO_NUMBER`는 서식이 들어간 문자열을 숫자로 바꿉니다.

```sql
SELECT TO_DATE('2025-06-01', 'YYYY-MM-DD')       AS 날짜변환,
       TO_NUMBER('1,234,567', '999,999,999')     AS 숫자변환;
```

| 날짜변환 | 숫자변환 |
|---|---|
| 2025-06-01 | 1234567 |

## 5.7 NULL 처리 함수

4장에서 NULL이 "값이 없는 상태"라는 것을 배웠습니다. 조회 결과에 NULL이 그대로 나오면 보기에 좋지 않으므로, 다른 값으로 대체해서 표시하는 경우가 많습니다.

### COALESCE — NULL을 다른 값으로 대체

`COALESCE`는 나열한 값 중 **NULL이 아닌 첫 번째 값**을 반환합니다.

```
[문법]
COALESCE(값1, 값2 [, 값3 ...])
```

**예제 5-17.** 전화번호가 없는 고객은 "미등록"으로 표시합니다.

```sql
SELECT customer_name, phone, COALESCE(phone, '미등록') AS 연락처
FROM customers;
```

| customer_name | phone | 연락처 |
|---|---|---|
| 김민준 | 010-1111-2222 | 010-1111-2222 |
| 이서연 | 010-2222-3333 | 010-2222-3333 |
| 박도윤 | *(NULL)* | 미등록 |
| 최지우 | 010-4444-5555 | 010-4444-5555 |
| 정하은 | 010-5555-6666 | 010-5555-6666 |

**예제 5-18.** 별점만 남기고 내용을 쓰지 않은 리뷰를 안내 문구로 채웁니다.

```sql
SELECT review_id, rating, COALESCE(review_text, '(내용 없음)') AS 내용
FROM reviews;
```

| review_id | rating | 내용 |
|---|---|---|
| 1 | 5 | 음질이 정말 좋아요 |
| 2 | 4 | (내용 없음) |
| 3 | 5 | 입문서로 최고입니다 |
| 4 | 3 | 무난해요 |
| 5 | 2 | 사이즈가 작게 나와요 |

### NULLIF — 특정 값을 NULL로 바꾸기

`NULLIF(a, b)`는 두 값이 **같으면 NULL**을, 다르면 `a`를 반환합니다. `COALESCE`와 정확히 반대 방향의 도구입니다.

```sql
SELECT NULLIF(0, 0) AS n1, NULLIF(10, 0) AS n2;
```

| n1 | n2 |
|---|---|
| *(NULL)* | 10 |

가장 흔한 용도는 **0으로 나누는 오류를 막는 것**입니다. SQL에서 0으로 나누면 `division by zero` 오류가 발생하며 쿼리 전체가 실패합니다. 분모를 `NULLIF(값, 0)`으로 감싸면 0일 때 NULL이 되고, NULL로 나눈 결과는 오류 대신 NULL이 됩니다.

**예제 5-19.** 재고가 0인 상품이 섞여 있어도 오류 없이 계산합니다.

```sql
SELECT product_name, price, stock_quantity,
       ROUND(price / NULLIF(stock_quantity, 0), 1) AS 결과
FROM products
WHERE product_id IN (4, 6);
```

| product_name | price | stock_quantity | 결과 |
|---|---|---|---|
| 머그컵 | 12000.00 | 100 | 120.0 |
| 견과류 세트 | 25000.00 | 0 | *(NULL)* |

## 5.8 CASE 식으로 조건 분기하기

함수만으로는 "가격이 5만 원 이상이면 고가, 2만 원 이상이면 중가, 나머지는 저가"처럼 **조건에 따라 다른 값**을 만들 수 없습니다. 이럴 때 `CASE` 식을 사용합니다.

```
[문법]
CASE WHEN 조건1 THEN 값1
     [WHEN 조건2 THEN 값2 ...]
     [ELSE 기본값]
END
```

**예제 5-20.** 가격에 따라 상품을 세 등급으로 분류합니다.

```sql
SELECT product_name, price,
       CASE WHEN price >= 50000 THEN '고가'
            WHEN price >= 20000 THEN '중가'
            ELSE '저가'
       END AS 가격대
FROM products;
```

| product_name | price | 가격대 |
|---|---|---|
| 무선 이어폰 | 89000.00 | 고가 |
| 블루투스 키보드 | 45000.00 | 중가 |
| 스탠드 조명 | 32000.00 | 중가 |
| 머그컵 | 12000.00 | 저가 |
| 원두커피 1kg | 18000.00 | 저가 |
| 견과류 세트 | 25000.00 | 중가 |
| ... 외 4건 | | |

`CASE`는 **위에서부터 순서대로** 조건을 확인하고, 처음으로 참이 되는 `WHEN`의 값을 사용한 뒤 나머지는 건너뜁니다. 그래서 조건의 순서가 중요합니다. 위 예제에서 `price >= 20000`을 먼저 썼다면 89,000원짜리 상품도 "중가"로 분류됐을 것입니다.

`ELSE`를 생략하면 어떤 조건에도 걸리지 않은 행은 **NULL**이 됩니다.

```sql
SELECT product_name,
       CASE WHEN stock_quantity = 0 THEN '품절' END AS 상태
FROM products
WHERE product_id IN (1, 6);
```

| product_name | 상태 |
|---|---|
| 무선 이어폰 | *(NULL)* |
| 견과류 세트 | 품절 |

### 단순 CASE — 한 컬럼의 값을 비교할 때

하나의 컬럼을 여러 값과 비교만 한다면 더 간결한 형태를 쓸 수 있습니다.

```
[문법]
CASE 컬럼명 WHEN 값1 THEN 결과1
            [WHEN 값2 THEN 결과2 ...]
            [ELSE 기본값]
END
```

**예제 5-21.** 주문 상태를 짧은 표현으로 바꿉니다.

```sql
SELECT order_id, status,
       CASE status WHEN '배송완료' THEN '완료'
                   WHEN '배송중'   THEN '진행중'
                   WHEN '결제완료' THEN '준비중'
                   ELSE '기타'
       END AS 요약
FROM orders;
```

| order_id | status | 요약 |
|---|---|---|
| 1 | 배송완료 | 완료 |
| 2 | 배송완료 | 완료 |
| 3 | 배송중 | 진행중 |
| 4 | 결제완료 | 준비중 |
| 5 | 취소 | 기타 |
| 6 | 배송완료 | 완료 |

단순 CASE는 **등호 비교만** 가능합니다. `>=` 같은 범위 조건이 필요하다면 앞에서 본 `CASE WHEN` 형태를 써야 합니다.

## 5.9 함수는 중첩해서 쓸 수 있습니다

함수의 결과를 다른 함수의 입력으로 넣을 수 있습니다. 안쪽 함수가 먼저 계산되고, 그 결과가 바깥 함수로 전달됩니다.

**예제 5-22.** NULL을 대체한 뒤 그 길이를 구합니다.

```sql
SELECT customer_name,
       COALESCE(phone, '미등록') AS 연락처,
       LENGTH(COALESCE(phone, '미등록')) AS 길이
FROM customers
WHERE customer_id IN (1, 3);
```

| customer_name | 연락처 | 길이 |
|---|---|---|
| 김민준 | 010-1111-2222 | 13 |
| 박도윤 | 미등록 | 3 |

중첩이 세 단계를 넘어가면 읽기 어려워집니다. 그럴 때는 9장에서 배울 서브쿼리나 CTE로 단계를 나누는 편이 낫습니다.

## 요약

- 스칼라 함수는 행마다 하나의 결과를 돌려주며, 조회되는 행의 개수를 바꾸지 않는다
- 문자열은 `LENGTH`, `UPPER`, `SUBSTRING`, `SPLIT_PART`, `REPLACE`, `LPAD` 등으로 가공한다. `||`는 NULL이 섞이면 전체가 NULL이 되지만 `CONCAT`은 NULL을 무시한다
- 숫자는 `ROUND`, `TRUNC`, `CEIL`, `FLOOR`, `MOD` 등으로 다룬다
- 날짜는 정수를 더하면 일 단위로 계산되며, `EXTRACT`로 일부를 추출하고 `DATE_TRUNC`로 기준 시점을 만든다
- `CAST` 또는 `::`로 타입을 바꾸고, `TO_CHAR`로 출력 서식을 지정한다
- `DATE '2025-07-01'`처럼 타입 이름을 앞에 붙이는 표기는 문자열 상수의 타입을 지정하는 방법이며, 컬럼에는 쓸 수 없다
- `COALESCE`는 NULL을 다른 값으로 바꾸고, `NULLIF`는 특정 값을 NULL로 바꾼다. `NULLIF(값, 0)`은 0으로 나누는 오류를 막는 대표적인 방법이다
- `CASE`는 조건에 따라 다른 값을 반환하며, 위에서부터 처음 참이 되는 조건만 적용된다
