## 1.1 데이터베이스란 무엇인가

여러분이 온라인 쇼핑몰을 운영한다고 가정해 봅시다. 회원 정보, 상품 목록, 주문 내역을 어딘가에 저장해야 합니다. 처음에는 엑셀 파일 하나로 시작할 수도 있습니다. 하지만 회원이 몇만 명으로 늘어나고, 동시에 여러 직원이 데이터를 조회·수정해야 하고, 주문이 초 단위로 쌓인다면 엑셀 파일 하나로는 감당할 수 없습니다.

**데이터베이스**(**Database**)란 이렇게 많은 양의 데이터를 체계적으로 저장하고, 여러 사람(또는 프로그램)이 안전하게 동시에 접근할 수 있도록 관리하는 저장소입니다. 그리고 이 데이터베이스를 관리해 주는 소프트웨어를 **DBMS**(**Database Management System**, 데이터베이스 관리 시스템)라고 부릅니다.

## 1.2 파일로 데이터를 관리할 때의 한계

엑셀이나 텍스트 파일로 데이터를 관리하면 다음과 같은 문제가 생깁니다.

- **동시 접근 문제**: 두 명이 동시에 같은 파일을 수정하면 한쪽 작업이 사라질 수 있습니다
- **데이터 중복과 불일치**: 같은 고객 정보가 여러 파일에 중복 저장되면, 한쪽만 수정했을 때 정보가 서로 달라집니다
- **검색 성능**: 데이터가 수백만 건이 되면 파일에서 원하는 값을 찾는 데 오랜 시간이 걸립니다
- **데이터 무결성 보장 불가**: "가격은 반드시 0보다 커야 한다" 같은 규칙을 파일 자체는 강제할 수 없습니다
- **장애 복구의 어려움**: 프로그램이 갑자기 종료되었을 때 파일이 손상되기 쉽습니다

DBMS는 이 문제들을 해결하기 위해 만들어졌습니다. 여러 사용자의 동시 접근을 안전하게 조율하고(동시성 제어), 데이터 간의 규칙을 강제하고(무결성 제약), 장애가 나도 데이터를 복구할 수 있게(트랜잭션) 설계되어 있습니다. 이런 세부 내용은 뒤의 장에서 하나씩 다룹니다.

## 1.3 관계형 데이터베이스란 무엇인가

데이터베이스에는 여러 종류가 있지만, 이 교재에서 다루는 것은 **관계형 데이터베이스**(**RDBMS**, Relational Database Management System)입니다.

관계형 데이터베이스는 데이터를 **표**(테이블) 형태로 저장하고, 테이블과 테이블 사이의 **관계**(**Relation**)를 이용해 데이터를 연결합니다. 예를 들어 "고객" 테이블과 "주문" 테이블을 따로 두고, 각 주문이 어느 고객의 것인지를 연결 정보로 표시하는 방식입니다. 이 방식은 데이터 중복을 줄이고, 한 곳만 수정하면 관련된 모든 데이터가 일관성을 유지하도록 해 줍니다.

> 참고로 문서나 그래프 형태로 데이터를 저장하는 MongoDB, Neo4j 같은 **비관계형**(**NoSQL**) 데이터베이스도 있습니다. 이 교재에서는 다루지 않지만, "모든 데이터베이스가 표 형태는 아니다"라는 점만 기억해 두면 좋습니다.

## 1.4 테이블, 행, 열

관계형 데이터베이스의 데이터는 **테이블**(**Table**) 안에 저장됩니다. 테이블은 엑셀 시트와 비슷한 모양을 하고 있습니다.

| customer_id | customer_name | city |
|---|---|---|
| 1 | 김민준 | 서울 |
| 2 | 이서연 | 부산 |

- **테이블**(**Table**): 관련된 데이터를 모아 놓은 표 전체 (위 예시에서는 "고객" 정보를 담은 테이블)
- **열 / 컬럼**(**Column**): 세로 방향의 항목. `customer_id`, `customer_name`, `city`처럼 어떤 종류의 데이터를 저장할지 정의합니다
- **행**(**Row**): 가로 방향의 데이터 한 건. 위 표에서 "김민준, 서울" 한 줄이 하나의 행이며, 이것을 하나의 **레코드**라고도 부릅니다

이 교재에서는 앞으로 "행", "열 / 컬럼"이라는 용어를 사용합니다. 실무에서는 "로우(row)", "필드(field)"라는 표현도 섞어 쓰지만, 뜻은 같습니다.

## 1.5 DBMS와 Client 간의 요청/응답 — "서버로 서비스한다"는 것

데이터베이스는 대부분 **서버**(**Server**) 형태로 동작합니다. 즉, PostgreSQL이라는 프로그램이 컴퓨터 한 대(또는 클라우드)에서 항상 켜져 있고, 여러 **클라이언트**(**Client**)가 이 서버에 접속해서 데이터를 요청합니다.

```
[클라이언트]                          [DBMS 서버]
   psql, pgAdmin,        요청 →      PostgreSQL
   웹 애플리케이션 등      ← 응답        (데이터 저장소)
```

예를 들어 여러분이 psql이라는 프로그램(클라이언트)에서 "고객 목록을 보여줘"라는 SQL 문장을 보내면, PostgreSQL 서버가 이 요청을 받아 데이터를 찾아서 결과를 돌려줍니다. 웹사이트의 "로그인" 버튼을 눌렀을 때도 마찬가지입니다 — 웹 서버가 클라이언트가 되어 데이터베이스 서버에 "이 아이디와 비밀번호가 맞는 회원이 있는지" 요청을 보내는 것입니다.

이 구조 덕분에 하나의 데이터베이스 서버에 수십, 수백 개의 클라이언트(직원들의 PC, 웹사이트, 모바일 앱 등)가 동시에 접속해서 같은 데이터를 안전하게 이용할 수 있습니다. 앞으로 2장에서 설치할 psql, pgAdmin도 모두 "클라이언트"이고, 우리가 배우는 PostgreSQL은 "서버"입니다.

## 1.6 PostgreSQL 소개

**PostgreSQL**(흔히 "포스트그레스"라고 읽습니다)은 1986년 미국 버클리 대학에서 시작된 프로젝트를 기반으로 한 오픈소스 관계형 데이터베이스입니다.

주요 특징은 다음과 같습니다.

- **오픈소스이며 무료**: 라이선스 비용 없이 상업적으로도 자유롭게 사용할 수 있습니다
- **표준을 잘 지킴**: SQL 표준(ANSI SQL)을 상당히 충실하게 따르고 있어, 다른 DBMS로 이전하거나 배운 지식을 응용하기 좋습니다
- **확장성**: JSON 데이터 저장, 지리 정보(PostGIS), 전문 검색 등 다양한 기능을 확장 모듈로 추가할 수 있습니다
- **안정적인 트랜잭션 처리**: 대규모 서비스에서도 데이터 정합성을 보장하도록 설계되어 있습니다

MySQL, Oracle, SQL Server 같은 다른 RDBMS와 기본 개념(테이블, SQL 문법)은 대부분 같습니다. 다만 함수 이름이나 일부 문법에 차이가 있는데, 이 교재에서는 **PostgreSQL 기준 문법**으로 설명합니다. 다른 DBMS를 나중에 접하더라도 기본기는 거의 그대로 통합니다.

---

## 요약

- 데이터베이스는 대량의 데이터를 안전하고 체계적으로 관리하기 위한 저장소이며, DBMS가 이를 관리한다
- 관계형 데이터베이스는 데이터를 테이블(표) 형태로 저장하고, 테이블 간 관계로 데이터를 연결한다
- 테이블은 열(컬럼)과 행(레코드)으로 구성된다
- 데이터베이스는 서버로 동작하며, 클라이언트가 요청을 보내고 서버가 응답하는 구조로 여러 사용자가 동시에 이용한다
- PostgreSQL은 오픈소스 관계형 데이터베이스이며, SQL 표준을 충실히 따른다

## 정답 및 해설

**문제 1**
예: 여러 사람이 동시에 수정할 때 발생하는 충돌, 같은 정보가 여러 파일에 중복 저장되어 생기는 불일치, 대량 데이터에서의 느린 검색 속도, 잘못된 값이 입력되는 것을 막을 방법이 없다는 점 등.

**문제 2**
테이블은 표 전체(상품 목록), 열은 `product_name`, `price`처럼 세로 항목, 행은 "무선 이어폰, 89000"처럼 가로 한 줄의 데이터입니다.

**문제 3**
DBMS(서버)는 항상 켜져 있는 프로그램으로 데이터를 저장하고 있고, psql이나 웹 애플리케이션 같은 클라이언트가 서버에 요청을 보내면 서버가 데이터를 찾아 응답을 돌려주는 구조를 말합니다. 여러 클라이언트가 하나의 서버에 동시에 접속할 수 있습니다.

**문제 4**
`MongoDB`. MongoDB는 데이터를 테이블(표)이 아닌 문서(document) 형태로 저장하는 비관계형(NoSQL) 데이터베이스이기 때문입니다.

**문제 5**
예: 오픈소스이며 무료로 사용할 수 있다, SQL 표준을 충실히 따른다, JSON 저장이나 PostGIS 등 확장 기능이 풍부하다, 트랜잭션 처리가 안정적이다 등 (두 가지 이상 서술하면 정답).
