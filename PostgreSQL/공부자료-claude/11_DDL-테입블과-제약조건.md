# 11장. DDL — 테이블과 제약조건

## 학습 목표

- 데이터베이스와 테이블을 생성하고 삭제할 수 있다
- 상황에 맞는 데이터 타입을 선택할 수 있다
- 제약조건으로 잘못된 데이터가 들어오는 것을 막을 수 있다
- `ALTER TABLE`로 이미 만든 테이블의 구조를 변경할 수 있다

그래서 이 장의 실습에는 **`study_`로 시작하는 별도의 테이블**만 사용합니다. `shop_db` 안에 만들어도 기존 7개 테이블과 이름이 겹치지 않으므로 안전합니다.

## 11.1 데이터베이스 생성과 삭제

```sql
CREATE DATABASE 데이터베이스명;
DROP DATABASE 데이터베이스명;
```

2장에서 `CREATE DATABASE shop_db`로 이미 한 번 사용해 봤습니다. 몇 가지 주의사항이 있습니다.

- **접속 중인 데이터베이스는 삭제할 수 없습니다.** 다른 데이터베이스로 전환한 뒤(`\c postgres`) 삭제해야 합니다
- `DROP DATABASE`는 **되돌릴 수 없습니다.** 안에 있던 모든 테이블과 데이터가 함께 사라집니다
- 없는 데이터베이스를 지울 때 오류를 피하려면 `DROP DATABASE IF EXISTS 이름`을 씁니다

## 11.2 자주 사용하는 데이터 타입

테이블을 만들 때는 각 컬럼에 **어떤 종류의 값이 들어올지** 지정해야 합니다. 타입을 정확히 고르면 잘못된 값이 저장되는 것을 데이터베이스가 막아 줍니다.

### 숫자

| 타입 | 설명 | 언제 쓰나 |
|---|---|---|
| `SMALLINT`(`int2`) | 작은 정수 (16bit) | 별점, 코드값 (±32,767) |
| `INTEGER` (`int`, `int4`) | 정수 (32bit)  | 수량, ID, 나이 (약 ±21억)|
| `BIGINT` (`int8`) | 큰 정수(64bit) | 대용량 ID, 조회수 (약 ±922경)|
| `NUMERIC(전체자릿수, 소수자릿수)` | 정확한 소수(고정 소수점) | **금액**, 비율 |
| `REAL`(`float4`) | 부동소수점 (32byte) |과학,통계,측정값-낮은 정밀도로 충분한 경우 |
|`DOUBLE PRECISION` (`float8`)| 부동소수점(64byte)|과학,통계,측정값-약간의 오차 허용|

> **금액에는 반드시 `NUMERIC`을 쓰세요.** 부동소수점 타입은 내부적으로 근사값을 저장하므로 계산할 때 미세한 오차가 쌓입니다. `shop_db`의 `price`가 `NUMERIC(10,2)`인 것도 이 때문입니다.

### 문자

| 타입 | 설명 |
|---|---|
| `CHAR(n)` | n글자의 고정길이 문자열. 항상 n글자인 고정 길이된다 (부족하면 공백으로 채움) |
| `VARCHAR(n)` | 최대 n글자까지의 가변 길이 문자열 |
| `TEXT` | 길이 제한 없는 문자열 |

`CHAR`는 짧은 값을 넣어도 뒤를 공백으로 채웁니다.  
글자수가 자릿수보도 적으면 공백이 붙으므로, 글자수가 일정한 데이터에서만 사용하고 **특별한 이유가 없다면 `VARCHAR`나 `TEXT`를 쓰세요.**

### 날짜와 시간

| 타입 | 저장하는 것 | 예 |
|---|---|---|
| `DATE` | 날짜만 | 2025-06-01 |
| `TIME` | 시각만 | 14:30:00 |
| `TIMESTAMP` | 날짜 + 시각 | 2025-06-01 14:30:00 |
| `TIMESTAMPTZ` | 날짜 + 시각 + 시간대 | 시차가 중요한 경우 |
| `INTERVAL` | 기간 | 3 days |

### 그 밖에

| 타입 | 설명 |
|---|---|
| `BOOLEAN` | 참/거짓 (`TRUE`, `FALSE`, `NULL`) |
| `JSONB` | JSON 데이터 (PostgreSQL의 강점 중 하나) |
| `UUID` | 고유 식별자 |

> 전체 타입 목록은 **부록 A**를 참고하세요. 입문 단계에서는 위 표에 나온 것만 알아도 충분합니다.

## 11.3 테이블 생성 — CREATE TABLE

```
[문법]
CREATE TABLE 테이블명 (
    컬럼명 데이터타입 [제약조건],
    컬럼명 데이터타입 [제약조건],
    ...
);
```

**예제 11-1.** 스터디 회원 테이블을 만듭니다.

```sql
CREATE TABLE study_members (
    member_id    SERIAL PRIMARY KEY,
    member_name  VARCHAR(50) NOT NULL,
    email        VARCHAR(100) UNIQUE,
    age          INT CHECK (age >= 0),
    grade        VARCHAR(10) NOT NULL DEFAULT '일반',
    joined_at    DATE NOT NULL DEFAULT CURRENT_DATE
);
```

2장에서 배운 `\d 테이블명`으로 구조를 확인할 수 있습니다.

```
\d study_members
```

| Column | Type | Nullable | Default |
|---|---|---|---|
| member_id | integer | not null | nextval('study_members_member_id_seq') |
| member_name | character varying(50) | not null | |
| email | character varying(100) | | |
| age | integer | | |
| grade | character varying(10) | not null | '일반' |
| joined_at | date | not null | CURRENT_DATE |

값을 하나 넣어 봅시다.

```sql
INSERT INTO study_members (member_name, email, age)
VALUES ('김철수', 'chulsoo@example.com', 25);

SELECT * FROM study_members;
```

| member_id | member_name | email | age | grade | joined_at |
|---|---|---|---|---|---|
| 1 | 김철수 | chulsoo@example.com | 25 | 일반 | *(오늘 날짜)* |

`member_id`와 `grade`, `joined_at`은 입력하지 않았는데도 값이 채워졌습니다. 각각 자동 증가와 기본값이 동작한 결과입니다.

## 11.4 자동 증가 컬럼

행마다 고유한 번호를 자동으로 붙이는 기능입니다. PostgreSQL에는 두 가지 방법이 있습니다.

### SERIAL

```sql
member_id SERIAL PRIMARY KEY
```

`SERIAL`은 타입처럼 보이지만 실제로는 **축약 표기**입니다. PostgreSQL이 내부적으로 시퀀스를 만들고 기본값으로 연결해 줍니다.

| 표기 | 실제 타입 |
|---|---|
| `SMALLSERIAL` | `SMALLINT` + 시퀀스 |
| `SERIAL` | `INTEGER` + 시퀀스 |
| `BIGSERIAL` | `BIGINT` + 시퀀스 |

### IDENTITY — 표준 SQL 방식

```sql
course_id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY
```

**예제 11-2.** 강의 테이블을 IDENTITY로 만듭니다.

```sql
CREATE TABLE study_courses (
    course_id   INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    course_name VARCHAR(100) NOT NULL,
    member_id   INT REFERENCES study_members(member_id)
);

INSERT INTO study_courses (course_name, member_id) VALUES ('SQL 입문', 1);
```

`GENERATED ALWAYS`는 값을 **직접 지정하는 것을 막습니다.**

```sql
INSERT INTO study_courses (course_id, course_name) VALUES (10, '직접지정');
```

```
ERROR:  cannot insert a non-DEFAULT value into column "course_id"
DETAIL:  Column "course_id" is an identity column defined as GENERATED ALWAYS.
```

직접 지정을 허용하려면 `GENERATED BY DEFAULT AS IDENTITY`를 씁니다.

> **어느 것을 쓸까**: `IDENTITY`가 표준 SQL이고 실수로 값을 덮어쓰는 것을 막아 주므로 새로 만드는 테이블에는 권장됩니다. `SERIAL`은 표기가 짧고 기존 코드에 많이 남아 있어 여전히 흔히 보입니다. 이 교재의 `shop_db`는 짧은 표기를 위해 `SERIAL`을 썼습니다.

### 번호는 중간에 건너뛸 수 있습니다

입문자가 자주 놀라는 부분입니다. 시퀀스는 **INSERT가 실패해도 번호를 되돌리지 않습니다.**

앞에서 제약조건 위반으로 몇 번 INSERT가 실패한 뒤 새 회원을 넣어 보면 이렇게 됩니다.

```sql
INSERT INTO study_members (member_name) VALUES ('정수진');
SELECT member_id, member_name FROM study_members ORDER BY member_id;
```

| member_id | member_name |
|---|---|
| 1 | 김철수 |
| 5 | 정수진 |

2, 3, 4번이 비어 있습니다. 실패한 INSERT들이 번호를 이미 가져갔기 때문입니다. **이것은 정상 동작입니다.** 여러 사용자가 동시에 INSERT할 때 번호가 겹치지 않게 하려면 되돌릴 수 없기 때문입니다. ID는 "고유한 식별자"일 뿐 "몇 번째 행인지"를 뜻하지 않는다는 점을 기억하세요.

## 11.5 제약조건

**제약조건**(**Constraint**)은 테이블에 들어올 수 있는 값의 규칙입니다. 규칙을 어기는 데이터는 **데이터베이스가 거부**합니다.

애플리케이션에서 검사하면 되지 않을까 싶지만, 프로그램은 여러 개일 수 있고 사람이 직접 SQL을 실행하기도 합니다. 제약조건은 **어떤 경로로 들어오든** 적용되는 마지막 방어선입니다.

| 제약조건 | 의미 |
|---|---|
| `PRIMARY KEY` | 각 행을 고유하게 식별. NULL 불가 + 중복 불가 |
| `FOREIGN KEY` | 다른 테이블에 존재하는 값만 허용 |
| `UNIQUE` | 중복 불가 (NULL은 여러 개 허용) |
| `NOT NULL` | NULL 불가 |
| `CHECK` | 지정한 조건을 만족해야 함 |
| `DEFAULT` | 값을 주지 않으면 대신 채울 값 |

### 각 제약조건이 하는 일

제약조건을 어기면 어떤 오류가 나는지 직접 확인해 봅시다.

**NOT NULL** — 이름 없이 회원을 등록하려 하면

```sql
INSERT INTO study_members (email) VALUES ('a@example.com');
```
```
ERROR:  null value in column "member_name" of relation "study_members"
        violates not-null constraint
```

**UNIQUE** — 이미 등록된 이메일을 다시 쓰면

```sql
INSERT INTO study_members (member_name, email) VALUES ('이영희', 'chulsoo@example.com');
```
```
ERROR:  duplicate key value violates unique constraint "study_members_email_key"
DETAIL:  Key (email)=(chulsoo@example.com) already exists.
```

**CHECK** — 나이에 음수를 넣으면

```sql
INSERT INTO study_members (member_name, age) VALUES ('박민수', -5);
```
```
ERROR:  new row for relation "study_members" violates check constraint
        "study_members_age_check"
```

**FOREIGN KEY** — 존재하지 않는 회원을 참조하면

```sql
INSERT INTO study_courses (course_name, member_id) VALUES ('없는회원', 999);
```
```
ERROR:  insert or update on table "study_courses" violates foreign key constraint
        "study_courses_member_id_fkey"
DETAIL:  Key (member_id)=(999) is not present in table "study_members".
```

`FOREIGN KEY`는 반대 방향도 막습니다. 자식 행이 참조하고 있는 부모를 삭제하려 하면 거부됩니다.

```sql
DELETE FROM study_members WHERE member_id = 1;
```
```
ERROR:  update or delete on table "study_members" violates foreign key constraint
DETAIL:  Key (member_id)=(1) is still referenced from table "study_courses".
```

이것이 7장에서 말한 **"데이터 무결성"**입니다. 주문은 남아 있는데 고객이 사라지는 상황을 데이터베이스가 원천적으로 막아 줍니다.

### PRIMARY KEY와 UNIQUE의 차이

둘 다 중복을 막지만 차이가 있습니다.

| | PRIMARY KEY | UNIQUE |
|---|---|---|
| NULL 허용 | 불가 | **가능** (여러 개도 가능) |
| 테이블당 개수 | **1개** | 여러 개 |
| 의미 | 이 테이블의 대표 식별자 | 단순히 값이 겹치면 안 됨 |

`study_members`에서 `email`이 `UNIQUE`인 것은 "이메일은 겹치면 안 되지만, 아직 등록하지 않은 회원이 있을 수 있다"는 뜻입니다.

### 테이블 레벨 제약조건과 이름 붙이기

지금까지는 컬럼 뒤에 제약조건을 붙였습니다. 컬럼 정의를 모두 쓴 뒤 **따로 선언**할 수도 있으며, 이때 `CONSTRAINT 이름`으로 원하는 이름을 줄 수 있습니다.

**예제 11-3.** 수강 신청 테이블을 만듭니다.

```sql
CREATE TABLE study_enrollments (
    member_id  INT NOT NULL,
    course_id  INT NOT NULL,
    score      INT,
    CONSTRAINT pk_enrollments PRIMARY KEY (member_id, course_id),
    CONSTRAINT fk_enroll_member FOREIGN KEY (member_id)
        REFERENCES study_members(member_id) ON DELETE CASCADE,
    CONSTRAINT chk_score CHECK (score BETWEEN 0 AND 100)
);
```

여기서 두 가지가 새롭습니다.

**첫째, 복합 기본키입니다.** `PRIMARY KEY (member_id, course_id)`는 두 컬럼의 **조합**이 유일해야 한다는 뜻입니다. 같은 회원이 같은 강의를 두 번 신청하는 것은 막히지만, 다른 강의는 신청할 수 있습니다.

```sql
INSERT INTO study_enrollments (member_id, course_id, score) VALUES (1, 1, 70);
```
```
ERROR:  duplicate key value violates unique constraint "pk_enrollments"
DETAIL:  Key (member_id, course_id)=(1, 1) already exists.
```

**둘째, `ON DELETE CASCADE`입니다.** 부모 행이 삭제되면 이를 참조하는 자식 행도 **함께 삭제**됩니다.

```sql
DELETE FROM study_members WHERE member_id = 5;   -- 정상 실행됨
SELECT * FROM study_enrollments;
```

5번 회원의 수강 신청 기록이 자동으로 사라집니다. 옵션은 다음과 같습니다.

| 옵션 | 부모가 삭제될 때 |
|---|---|
| `NO ACTION` (기본값) | 자식이 있으면 삭제를 **거부** |
| `CASCADE` | 자식도 함께 삭제 |
| `SET NULL` | 자식의 참조 컬럼을 NULL로 |

> **주의**: `CASCADE`는 편리하지만 위험합니다. 부모 하나를 지웠다가 예상보다 많은 데이터가 연쇄적으로 사라질 수 있습니다. 기본값인 `NO ACTION`으로 두고 삭제 순서를 직접 관리하는 편이 안전한 경우가 많습니다.

**제약조건에 이름을 붙이는 이유**는 오류 메시지 때문입니다. 이름을 주지 않으면 `study_members_age_check`처럼 자동 생성된 이름이 나오는데, `chk_score`처럼 의미가 담긴 이름을 붙여 두면 어떤 규칙을 어겼는지 바로 알 수 있습니다. 나중에 제약조건을 삭제할 때도 이름이 필요합니다.

## 11.6 테이블 수정 — ALTER TABLE

이미 만든 테이블의 구조를 바꿉니다.

| 작업 | 문법 |
|---|---|
| 컬럼 추가 | `ALTER TABLE 테이블 ADD COLUMN 컬럼 타입;` |
| 컬럼 삭제 | `ALTER TABLE 테이블 DROP COLUMN 컬럼;` |
| 컬럼 이름 변경 | `ALTER TABLE 테이블 RENAME COLUMN 기존 TO 새이름;` |
| 타입 변경 | `ALTER TABLE 테이블 ALTER COLUMN 컬럼 TYPE 새타입;` |
| 기본값 지정 | `ALTER TABLE 테이블 ALTER COLUMN 컬럼 SET DEFAULT 값;` |
| NOT NULL 지정 | `ALTER TABLE 테이블 ALTER COLUMN 컬럼 SET NOT NULL;` |
| NOT NULL 해제 | `ALTER TABLE 테이블 ALTER COLUMN 컬럼 DROP NOT NULL;` |
| 제약조건 추가 | `ALTER TABLE 테이블 ADD CONSTRAINT 이름 조건;` |
| 제약조건 삭제 | `ALTER TABLE 테이블 DROP CONSTRAINT 이름;` |
| 테이블 이름 변경 | `ALTER TABLE 기존 RENAME TO 새이름;` |

**예제 11-4.** 여러 변경을 차례로 적용합니다.

```sql
ALTER TABLE study_members ADD COLUMN phone VARCHAR(20);
ALTER TABLE study_members RENAME COLUMN phone TO contact;
ALTER TABLE study_members ALTER COLUMN member_name TYPE VARCHAR(100);
ALTER TABLE study_members ALTER COLUMN grade SET DEFAULT '신규';
ALTER TABLE study_members ADD CONSTRAINT chk_age_max CHECK (age <= 150);
```

`\d study_members`로 확인하면 `member_name`이 `varchar(100)`으로, `grade`의 기본값이 `'신규'`로 바뀌어 있고 `chk_age_max` 제약조건이 추가되어 있습니다.

> **자주 하는 실수**: 이미 데이터가 들어 있는 테이블에 `SET NOT NULL`이나 `CHECK`를 추가할 때, **기존 데이터가 새 규칙을 위반하면 오류가 납니다.** 예를 들어 NULL이 섞여 있는 컬럼에 `SET NOT NULL`을 걸 수 없습니다. 먼저 12장에서 배울 `UPDATE`로 기존 데이터를 정리한 뒤 제약조건을 추가해야 합니다.

## 11.7 테이블 삭제 — DROP과 TRUNCATE

### DROP TABLE — 테이블 자체를 없앰

```sql
DROP TABLE study_members;
```

참조하는 테이블이 있으면 거부됩니다.

```
ERROR:  cannot drop table study_members because other objects depend on it
DETAIL:  constraint study_courses_member_id_fkey on table study_courses
         depends on table study_members
HINT:  Use DROP ... CASCADE to drop the dependent objects too.
```

해결 방법은 두 가지입니다. **자식 테이블부터 순서대로 지우거나**, `DROP TABLE study_members CASCADE`로 의존 관계까지 한 번에 지우는 것입니다. `CASCADE`는 다른 테이블의 제약조건까지 말없이 삭제하므로 신중하게 쓰세요.

없는 테이블을 지울 때 오류를 피하려면 `DROP TABLE IF EXISTS 이름`을 씁니다. 2장의 `shop_db_seed.sql` 맨 앞에서 쓴 표기가 바로 이것입니다.

### TRUNCATE — 데이터만 전부 삭제

```sql
TRUNCATE TABLE study_enrollments;
```

**테이블 구조는 남기고 모든 행만** 지웁니다.

| | DROP TABLE | TRUNCATE | DELETE |
|---|---|---|---|
| 테이블 구조 | 삭제됨 | 남음 | 남음 |
| 조건 지정 | — | 불가 (전체) | `WHERE` 가능 |
| 속도 | — | 매우 빠름 | 느림 |
| 분류 | DDL | DDL | DML |

`DELETE`는 12장에서 배웁니다. **`TRUNCATE`는 `WHERE`를 쓸 수 없으므로 항상 전부 지운다**는 점을 기억하세요. 일부만 지우려면 `DELETE`를 써야 합니다.

## 요약

- 테이블은 `CREATE TABLE`로 만들고, 각 컬럼에 데이터 타입을 지정한다. 금액에는 `NUMERIC`을 쓴다
- `SERIAL`과 `IDENTITY`는 번호를 자동으로 붙여 준다. INSERT가 실패해도 번호는 되돌아가지 않는다
- 제약조건은 잘못된 데이터를 데이터베이스 차원에서 막는 마지막 방어선이다
- `PRIMARY KEY`는 NULL 불가에 테이블당 하나지만, `UNIQUE`는 NULL을 허용하고 여러 개 둘 수 있다
- `FOREIGN KEY`는 없는 부모를 참조하는 것도, 자식이 있는 부모를 지우는 것도 막는다
- 제약조건에 이름을 붙이면 오류 메시지를 읽기 쉽고 나중에 삭제하기도 편하다
- `ALTER TABLE`로 구조를 바꿀 때, 기존 데이터가 새 규칙을 위반하면 실패한다
- `DROP TABLE`은 구조까지, `TRUNCATE`는 데이터만 지운다. `TRUNCATE`에는 `WHERE`를 쓸 수 없다

## 정답 및 해설

**문제 1**
```sql
CREATE TABLE study_books (
    book_id  SERIAL PRIMARY KEY,
    title    VARCHAR(50) NOT NULL,
    price    NUMERIC(10,2)
);
```
`SERIAL` 대신 `INT GENERATED ALWAYS AS IDENTITY`를 써도 됩니다. 가격에 `REAL`이나 `FLOAT`을 쓰면 계산 오차가 생기므로 `NUMERIC`이 정답입니다.

**문제 2**
```sql
ALTER TABLE study_books
ADD COLUMN published_at DATE NOT NULL DEFAULT CURRENT_DATE;
```

**문제 3**
```sql
ALTER TABLE study_books
ADD CONSTRAINT chk_book_price CHECK (price > 0);
```

**문제 4**
```sql
INSERT INTO study_books (title, price) VALUES ('테스트', 0);
```
```
ERROR:  new row for relation "study_books" violates check constraint "chk_book_price"
```
제약조건에 직접 이름을 붙였기 때문에 오류 메시지에 `chk_book_price`가 그대로 나옵니다. 이름을 붙이지 않았다면 `study_books_price_check`처럼 자동 생성된 이름이 나왔을 것입니다.

**문제 5**
```sql
ALTER TABLE study_books
ALTER COLUMN title TYPE VARCHAR(100);
```
길이를 **늘리는** 것은 문제없지만, 줄일 때는 기존 데이터가 새 길이를 초과하면 오류가 납니다.

**문제 6**
```sql
CREATE TABLE study_authors (
    author_id SERIAL PRIMARY KEY,
    name      VARCHAR(50) NOT NULL,
    email     VARCHAR(100) UNIQUE
);
```

**문제 7**
```sql
ALTER TABLE study_books ADD COLUMN author_id INT;

ALTER TABLE study_books
ADD CONSTRAINT fk_book_author FOREIGN KEY (author_id)
REFERENCES study_authors(author_id);
```
컬럼 추가와 외래키 지정을 한 번에 쓸 수도 있습니다.
```sql
ALTER TABLE study_books
ADD COLUMN author_id INT REFERENCES study_authors(author_id);
```

**문제 8**
```sql
INSERT INTO study_books (title, price, author_id) VALUES ('없는작가', 10000, 999);
```
```
ERROR:  insert or update on table "study_books" violates foreign key constraint
        "fk_book_author"
DETAIL:  Key (author_id)=(999) is not present in table "study_authors".
```

**문제 9**
```sql
CREATE TABLE study_book_tags (
    book_id  INT NOT NULL REFERENCES study_books(book_id),
    tag_name VARCHAR(30) NOT NULL,
    CONSTRAINT pk_book_tags PRIMARY KEY (book_id, tag_name)
);
```
복합 기본키는 컬럼 뒤에 붙일 수 없으므로 **반드시 테이블 레벨**로 선언해야 합니다. 이렇게 하면 같은 도서에 같은 태그를 두 번 달 수는 없지만, 서로 다른 태그는 얼마든지 달 수 있습니다.

**문제 10**
```sql
DROP TABLE study_book_tags;
DROP TABLE study_books;
DROP TABLE study_authors;
```
**자식 테이블부터 지워야 합니다.** `study_book_tags`가 `study_books`를 참조하고, `study_books`가 `study_authors`를 참조하므로 참조하는 쪽이 먼저입니다. 순서를 지키지 않으면 `cannot drop table ... because other objects depend on it` 오류가 납니다.

순서를 신경 쓰지 않으려면 `DROP TABLE study_authors CASCADE`처럼 `CASCADE`를 쓸 수 있지만, 무엇이 함께 지워지는지 모른 채 실행하게 되므로 권장하지 않습니다.
